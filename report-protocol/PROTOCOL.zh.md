# 默认汇报协议

收到后立即生效，一直执行，直到用户说停。

## 1. 频率
- 每 30 分钟汇报一次。用定时唤醒，不要空转轮询。
- 时间一律用美国中部时间（CST），并写明 CST。

## 2. 汇报格式

**汇报 · HH:MM CST**

先用一句话说总体情况：本波次一共几个实验、做完几个、预计全部完成的时间。

再列本波次全部实验的表格，从第一个列到最后一个，每个实验一行：

| # | 实验 | 状态 | 结果 / ETA | 备注 |
|---|---|---|---|---|
| 1 | … | ✅ 完成 | 关键指标 | |
| 2 | … | 🔄 进行中 | 进度，ETA 几点几分 CST | |
| 3 | … | ⏳ 排队 | ETA 几点几分 CST | |
| 4 | … | ❌ 失败 | 失败原因，是否重跑 | |

- 已完成的写结果，没完成的写 ETA。
- 表格最后一行写整个波次预计全部完成的时间。

然后写"与上次相比的变化"，最多 3 条。

## 3. 遇到需要用户决定的问题
- 每个问题编一个号（Q1、Q2…），写出可选项，并标明你的默认选择及理由。
- 提出后 30 分钟用户没回复，就按默认选择执行，不要停工。
- 以下几类不能按默认执行，只列出来等用户回复。同时继续做不受影响的其他工作。
  - 对外动作：push、开 PR、发布、给别人发消息。
  - 删除无法恢复的数据。
  - 明显超出原计划的新花费。
  - 用户明确说过要自己决定的事。

## 4. 汇报结尾
只要有待决问题，每次汇报都必须以这一段结尾：

**需要你回复**
1. 已按默认执行（可推翻）：编号、问题、我做了什么、怎么撤回。
2. 仍需你回复：编号、问题、可选项、我的默认选择、为什么不能自己定。

没有问题时，结尾写"无需回复"。

## 5. 持续执行
- 新波次开始时，表格换成新波次的全部实验。
- 用户的回复优先于默认选择。被推翻的决定要立刻撤回，并在下次汇报里说明。
